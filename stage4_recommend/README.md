# Stage4 · 电商推荐系统（协同过滤）

推荐系统的本地可运行实现：**UserCF / ItemCF 双路召回 + 留一法离线评估 + 冷启动兜底**。
在不依赖 Spark 集群的前提下，把推荐系统的核心链路跑通，并用指标证明它有效。

---

## 项目简介

推荐系统的工业链路是：**召回 → 排序 → 重排**。本阶段聚焦最关键的**召回层**，
实现两个最经典的协同过滤算法，并补齐两个常被忽略、但面试必问的环节：

1. **离线评估**：不做评估的模型等于没做——用留一法 + HR@5 证明算法有效（相对随机 14.6 倍）
2. **冷启动**：算不出相似度的用户怎么办——用热门兜底（`hot_items.csv`）

| 算法 | 核心思想 | 适用场景 |
|---|---|---|
| UserCF | 和我相似的人喜欢什么，就推荐什么 | 用户少、兴趣发散（新闻、资讯） |
| ItemCF | 和我交互过的商品相似的商品，就推荐什么 | 商品多、兴趣稳定（电商、视频），可解释性强 |

## 技术栈

| 用途 | 技术 |
|---|---|
| 建模 | Python 3.10、numpy（稀疏矩阵、余弦相似度、向量化打分） |
| 数据处理 | pandas（评分矩阵构建、抽样） |
| 评估 | 留一法（Leave-One-Out）+ HR@5 + 随机基线对比 |
| 生产对照 | Spark MLlib（ALS）、LSH / FAISS 近邻检索、LR→GBDT→DNN 排序 |

## 核心功能

| 功能 | 说明 |
|---|---|
| 评分矩阵构建 | 用户-商品矩阵（`pivot_table`），行为加权，控制稀疏度 |
| 规模抽样 | 商品被 ≥2 人交互、用户有 ≥2 次行为，取最活跃的 8,000 用户与 4,000 商品 |
| UserCF | 用户余弦相似度矩阵 → 相似用户兴趣加权 → Top-N |
| ItemCF | 商品余弦相似度矩阵 → 已交互商品传播打分 → Top-N |
| 留一法评估 | 隐藏每个用户权重最高的 1 个交互，计算 HR@5 并与随机基线对比 |
| 冷启动兜底 | 购买/加购最热 TOP20（`hot_items.csv`）填充无推荐用户 |
| 结果落表 | `recommendations.csv`（user_id, algorithm, rank, item_id, score） |

## 运行结果

**评估报告（`evaluation.txt`）**

```
建模矩阵：8,000 用户 × 3,868 商品，非零占比 0.0612%
参与评估用户数：2,382（各隐藏 1 个最重交互做测试）

UserCF   HR@5 = 1.89%    相对随机基线 14.6 倍
ItemCF   HR@5 = 1.89%    相对随机基线 14.6 倍
随机推荐  HR@5 = 0.1293%（基线：候选池平均 3,866 个商品）
```

| 产出文件 | 内容 |
|---|---|
| `recommendations.csv` | 5,934 行召回结果（前 1,000 用户 × 2 算法 × Top3） |
| `hot_items.csv` | 20 个热门商品（冷启动兜底） |
| `evaluation.txt` | 评估报告 + 解读 |

## 技术亮点

1. **有评估、有基线**：HR@5 = 1.89% 单独看没有意义，配上"随机基线 0.1293%、提升 14.6 倍"
   才是可辩护的结论。候选池大小对随机基线的影响也一并给出（3,866 个商品）。
2. **把"为什么必须抽样"算清楚**：全量 23 万用户 × 27 万商品，item-item 相似度矩阵有
   27 万² ≈ 730 亿个元素，单机内存装不下；脚本用"活跃用户 + 高频商品"抽样把规模降到可算，
   并在解读里说明代价（长尾被过滤、推荐偏热门）与工业界的解法（Spark 分布式 + LSH/FAISS）。
3. **冷启动不是附属品**：脚本显式输出"某用户拿不到推荐"的例子，并给出兜底表，
   把教科书写成可落地的方案。
4. **纯 numpy 实现**：不依赖 scikit-learn / surprise，相似度与打分全部向量化，
   便于理解算法本质（矩阵乘法即协同过滤的全部运算）。

## 常见问题

- **为什么我的用户拿不到推荐**：该用户在筛选后的矩阵里没有邻居（无共同交互 → 余弦相似度为 0），
  线上应回落到热门/类目热门兜底。
- **HR@5 只有 1.89% 是不是太差**：单日 10 小时的数据极度稀疏（非零占比 0.06%），
  学界在同类数据集上也是低个位数；关键是与随机基线的倍数关系。
- **想提升效果**：① 换 ALS 做隐语义召回；② 引入时间衰减（旧行为降权）；
  ③ 加入价格/类目等侧特征做多路召回；④ 扩充数据窗口（完整 9 天数据）。
