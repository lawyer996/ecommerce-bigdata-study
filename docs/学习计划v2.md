# 电商×大数据 12周学习计划（v2 求职实战版）

> 定位：替代 13 周方案的落地版。原则——**真实数据、先单机后集群、每周可展示、对准简历**。
> 仓库：https://github.com/lawyer996/ecommerce-bigdata-study（目录结构沿用现有四阶段命名）

## 与原 13 周方案的关键差异（为什么这么改）

| 调整点 | 原方案 | 本方案 | 理由 |
|---|---|---|---|
| 数据 | 自造样本 csv / 后期才引入公开数据集 | **第1天就用真实数据集**（天池 UserBehavior 100万条子集） | 清洗/推荐/大屏全链路立刻有真实感，简历可写"百万级" |
| 集群 | 阶段2第1周搭 Hadoop 全家桶 | **前5周零集群**，第6周起用虚拟机集中2周搞定 | 配环境是最大劝退点；DuckDB/本地 Hive 可先跑通语法 |
| 实时 | Flink 或 Spark 二选一 | **Spark Structured Streaming 为主**，Flink SQL 作选修加分 | 岗位量、教程量、与阶段2的 Hive/Scala 生态衔接 |
| 提交 | 分模块 commit（原则性要求） | **每周固定节奏：代码 commit + weekN 笔记 + 1张图** | 作品集是按周长出来的，不是最后补的 |
| 验收 | 第13周统一收尾 | **每阶段结束 = 一次里程碑发布**（tag + README + 截图） | 求职随时可能开始，仓库必须任何时刻都能见人 |

## 数据集（第0周下载进仓库）

- 天池 **UserBehavior**（淘宝用户行为，2017-11~12）：取 100 万条子集（约100MB），字段 user_id / item_id / category_id / behavior_type(pv,buy,cart,fav) / timestamp——正好匹配现有 stage2 SQL 的字段设计
- 备选：MovieLens（辅助练推荐冷启动对比）

## 仓库规范（比原方案强化两点）

1. commit 统一 `stageN-weekM: 内容`；每阶段末打 tag（v0.1~v1.0），面试时可直接给 tag 链接
2. 每周笔记固定放 `docs/notes/weekN.md`，三段式：本周做了什么 / 踩了什么坑 / 下周计划
3. 每个 stage 根目录 README 必含：项目简介、技术栈、运行步骤、**一张效果截图**、技术亮点（对应简历一句话）
4. 大文件（数据集、模型）不入 git，dataset 里只放下载脚本和说明

## 每阶段的简历输出（背下来）

- 阶段1：搭建电商核心指标体系（GMV/转化漏斗/RFM），百万级行为数据清洗与可视化
- 阶段2：设计 ODS-DWD-DWS-ADS 四层数仓，Hive SQL 跑批，产出日销售/活跃/热度报表
- 阶段3：Kafka+Spark 实时链路，窗口聚合实时 UV/成交额，ECharts 大屏秒级刷新
- 阶段4：ALS 协同过滤推荐，离线评估准确率/召回率/F1，冷启动热门兜底策略
