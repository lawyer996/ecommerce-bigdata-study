## 踩了什么坑

- **口径不一致（最值得记录）**：大屏第一版 RFM 结果和 `sql_analysis.sql` 对不上
  （一般发展客户 6820 vs 8010）。原因是 SQL 的 `TIMESTAMPDIFF(HOUR, ...)` 是**整点截断**，
  而 pandas 用小数小时，边界用户（如 6.5 小时）落进了更低的分档。
  → 统一为"取整后再打分"，重跑后六层逐行一致。
  **教训：同一个指标在 SQL 和 Python 两处实现时，"取整/舍入/时区"这类细节必须显式对齐，
  否则两边都对、数字却不一样。**
- **分母为 0 的指标要显式处理**：筛选掉"浏览"行为后 PV=0，转化率会显示 0.00%（误导）。
  改为显示 `—` 并给出提示，同时补一句"转化率分母是 PV"的说明。
  **教训：指标卡不能只做除法，必须处理分母为 0、样本过小等边界情况。**
- `pd.read_sql` 传 pymysql 原生连接会发 SQLAlchemy 告警，用 `warnings.catch_warnings()` 局部屏蔽。

## 一些设计取舍

- **只用 Streamlit 内置图表 + Altair，不引 Plotly**：少一个重依赖，换机器安装更快；
  Altair 是 Streamlit 的既有依赖，声明式语法改起来也快。
- **筛选器做成"全局联动"而不是每个图单独筛**：漏斗、RFM 这类指标必须和 PV 用同一份切片口径，
  分开筛很容易得出自相矛盾的结论。
- **明细表限制 1000 行 + 提供导出**：48 万行直接渲染会卡死浏览器，交互体验优先。
